# Binary reader proofs

The [WebAssembly grammar](../../../WebAssembly/WebAssembly/Binary/Module.lean) relates exact lists of bytes to raw Wasm modules. Itasca’s [source translation](Source.lean) maps extracted byte and syntax representations into those types. [Reconstruction](ReadModule.lean) supplies a reader representation for every independently encoded module. For a known module, `limitedReaderSpans` recovers its section and bounded body spans directly from the canonical witness.

A byte sequence determines a unique module even though a module can have several encodings. For example, Wasm permits some nonminimal LEB128 encodings. Reader proofs preserve the consumed bytes and remaining suffix so instruction and section boundaries can be recovered when composing readers. The [LEB128 proofs](LebReaders.lean) establish the cursor span for the actual spelling. The [module uniqueness theorem](../../../WebAssembly/WebAssembly/Binary/Unique.lean) composes token, code-entry and section prefix uniqueness inside WebAssembly.

For limits, table types and memory types, the reader contracts apply the WebAssembly production to the converted value and bytes. Soundness obtains index witnesses from the consumed span. Completeness uses those witnesses to split the original span and recover the next cursor. The byte round trips `Source.readerBytes_bytes` and `Source.bytes_readerBytes` recover the original lists in either direction. For instructions, `ImmediateWith` specializes the same opcode cases to each representation. For modules, `ModuleSectionsWith` fixes section order and tags for both representations.
